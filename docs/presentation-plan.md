# 발표 구성안 (초안 v0.1, 2026-11-25)

발표 10분 = 신민지 5분 + 정찬호 5분. 발표 자료 제출 마감 12/8.

## 1. 시간 배분
| 시간 | 발표자 | 내용 | 슬라이드 |
|---|---|---|---|
| 0:00~1:00 | 민지 | 프로젝트 소개: 어떤 게임인지, 3스테이지와 왕, 팀 분담 | 1~2 |
| 1:00~3:30 | 민지 | 설계: Combatant 인터페이스 중심 구조, 한 루프로 플레이어·적 처리, 출력·입력 분리 | 3~4 |
| 3:30~4:30 | 민지 | 협업: api/ 합의 규칙, GitHub 커밋 흐름, 설계문서·SRS 갱신 | 5 |
| 4:30~5:00 | 민지 | 찬호님께 인계(시연 준비 한 줄 소개) | - |
| 5:00~7:00 | 찬호 | 캐릭터와 전투 규칙: 전사·드래곤, 명중·치명타·피해, 스킬, 상태이상 | 6 |
| 7:00~9:00 | 찬호 | 시연(아래 시나리오) | 7 |
| 9:00~10:00 | 찬호 | 결과, 어려웠던 점, 배운 점, 마무리 | 8 |

(앞뒤 순서를 바꾸는 것도 가능: 시연을 민지님이 맡을 수도 있음. 확정은 둘이 협의.)

## 2. 슬라이드 구성 (8장)
1. 표지: 제목, 팀원, 역할
2. 개요: 게임 규칙 한 장 요약 (3스테이지, 왕 = 드래곤, 턴제)
3. 구조: 클래스 다이어그램(`docs/class-diagram.svg`)
4. 핵심 설계: 폴리모피즘으로 플레이어·적을 한 루프에서 처리, 턴 순서(priority→speed→파티 순서), 엔진은 출력하지 않고 Listener로 알림
5. 협업: 인터페이스 합의(api/), 커밋 기록, 문서 버전 관리
6. 캐릭터·규칙: 전사, 드래곤, 스킬, 상태이상 (찬호님 담당)
7. 시연: 실행 화면 캡처 + 라이브 시연
8. 정리: 결과, 한계, 배운 점

## 3. 시연 시나리오 (약 2분)
- 시드를 고정하고 입력 파일로 자동 진행해 실패 위험을 줄인다: `java ... Main < demo-input.txt`
- 보여줄 순서: 스테이지 1 기본 공격 → 방어 → 스킬(강타) → 상태이상(화상) 적용·감소 → 스테이지 3 드래곤 처치 → 클리어 메시지
- 예비: 라이브가 안 되면 미리 찍어 둔 실행 화면 캡처/녹화 사용

## 4. 준비 일정
| 날짜 | 할 일 |
|---|---|
| ~12/3 | 구현이 돌아가는 상태 확보, 시연용 입력 파일 만들기 |
| 12/4~6 | 슬라이드 제작, 실행 화면 캡처 수집 |
| 12/7 | 리허설(시간 재기: 5분씩 맞추기) |
| 12/8 | 발표 자료 제출 |

## 5. 개인 평가 대비
- 평가에 개인별 커밋 횟수, 동료 평가가 들어간다 → 각자 발표에서 자기 담당(파일, 커밋)을 구체적으로 언급
- 발표 질문 대비: "왜 인터페이스로 나눴나", "상태이상을 왜 게임이 보관하나", "턴 순서를 왜 한 번만 정렬하나"
